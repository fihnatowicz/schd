# Расписание

Статическая страница-расписание, отдаётся GitHub Pages из корня репозитория.
Зависимостей и сборщика нет: браузер получает ровно те файлы, что лежат в репозитории.

## Что где лежит

| Файл | Что это |
|---|---|
| `index.html` | разметка + блок `<script id="schedule">` с данными |
| `app.css` | вся тема: палитра, шрифты, карточки, состояния |
| `app.js` | логика: текущее/следующее занятие, часы, прокрутка, прогресс |
| `schedule.json` | расписание в читаемом виде — источник правды |
| `build/build.py` | разбирает xlsx в `schedule.json` и вшивает его в `index.html` |
| `hero.jpg` | баннер шапки |
| `sukuna.jpg` | фон страницы |
| `icon.png` | аватарка в шапке и иконка PWA |

## Как менять

**Дизайн или поведение** — правьте `app.css` / `app.js` напрямую. Пересобирать ничего не нужно,
достаточно обновить страницу.

**Расписание** — положите новый xlsx в корень (он в `.gitignore`, в репозиторий не попадёт) и выполните:

```sh
python build/build.py                       # пересобрать из schedule.json
python build/build.py file.xlsx             # разобрать xlsx (лист «1  акт»)
python build/build.py file.xlsx "1  акт"    # указать файл и лист явно
```

Для разбора xlsx нужен `openpyxl` (`pip install openpyxl`); для пересборки из `schedule.json` — нет.
Мелкие правки расписания проще внести прямо в `schedule.json` и прогнать скрипт без аргументов.

Имя и подзаголовок в шапке живут в `schedule.json` → `meta` (и в `META` внутри `build/build.py`,
откуда они берутся при разборе xlsx).
